## Method in one paragraph

A 12-qubit compact encoding (3 qubits per cube: the number 0..5 of the cube's legal choice, written in binary) searched
two ways. **QAOA** that starts in the equal mix of the 6 legal codes per cube and uses a per-cube mixer that never
leaves them, with an exact 4-local cost Hamiltonian, reaches 98.4 % at p = 24 (8,648 CX). **Grover** with an oracle
generated only from the rules (no knowledge of the answer) reaches 99.8 % at K = 19 (3,987 CX, thanks to an idle
qubit the transpiler uses as a clean ancilla). Random guessing is 0.049 % (any 12-bit string) to 0.15 %
(a random legal code). Brute force checks all 331,776 towers in 0.15 s, and we say so: no speedup is
claimed. For the Bonus, the same p = 24 angles trained at N = 4 are reused unchanged on `make_puzzle(n, seed)` with
seeds `{5: 16, 6: 86, 7: 68, 8: 4}` (each checked to have exactly 2 answers with `count_answers`): N = 5: 48.4 % (17 qubits, 14,266 CX); N = 6: 35.9 % (20 qubits, 22,476 CX); N = 7: 15.8 % (23 qubits, 28,142 CX); N = 8: 28.3 % (26 qubits, 38,752 CX).

## How to run

```bash
pip install -r requirements.txt
pytest -q                                   # offline unit tests (slow ones: pytest -m slow)
jupyter nbconvert --to notebook --execute --inplace solution.ipynb   # about 80 s here with RUN_HEAVY = False (about 5 min on a busy machine)
python scripts/make_slides.py               # rebuilds slides.pdf from results/
```

The notebook runs top to bottom in qBraid Lab with no edits and is saved with outputs. Two switches in its first code
cell: `RUN_HEAVY = False` loads the N = 6, 7, 8 Bonus rows from `results/heavy_rows.json` (written by
`scripts/run_heavy.py` with the same code and seed; the notebook prints their provenance and recomputes their exact
probabilities live); `True` recomputes them (about 15 minutes). `USE_QBRAID = False` runs everything on the local Aer
simulator; **`True` sends circuits to qBraid's SV1 simulator and spends credits** (about 0.375 credits per small job,
7.5 credits per simulated minute). The submission code in `src/runtime.py` only accepts `aws:aws:sim:sv1`, refuses any
`:qpu:` device, checks a credit quote first, never prints credentials, logs job ids to `results/jobs.json` and caches
counts in `results/sv1_counts/`. Seed 7 everywhere.

## Verified / not verified

**Verified:** every reported tower by `solves(tower_from(...))`; brute force 8 of 331,776 towers;
2 graph-level answers = `count_answers` on every instance (N = 4..8); the starter cost has exactly 2 zeros
among 6,561 candidates; our Hamiltonian equals the classical cost on all 1,296 legal codes and has exactly
2 zeros among all 4,096 strings; decoders on known answer strings in both bit orders; the marker trap of
the one-sided marker shown and fixed; the cost step equals `PauliEvolutionGate`; the mixer never leaves the legal
codes; sampled success rates agree with the exact ones within about two standard errors.
**Not verified:** any SV1 submission; behaviour on a QPU; Grover for N >= 6 (resource estimate only); gate counts on
Qiskit 1.3 (all counts are from qiskit 2.6.0). On Qiskit 1.3.3 (checked locally) `src/` imports and the QAOA code
is unchanged, but `PhaseOracleGate` does not exist there, so the Grover oracle falls back to a diagonal gate built from
the same rule: it marks the same states (tested) and its gate count is not comparable, so it is not reported.

## Honesty

The QAOA angles are trained by a classical simulation of the 6^4 legal cases, which is more work than checking them
directly; rows C3 and the Bonus rows show the circuit still works with angles that never saw the puzzle (C5 does not
count as that: its two ramp numbers were tuned on this puzzle). Grover
uses M = 2 from the classical `count_answers` (with unknown M one would use the BBHT schedule or quantum counting).
No quantum speedup is claimed. Thousands of CX gates are noiseless on SV1, but simulation time still costs credits
(7.5 per minute), and such circuits would not survive today's noisy hardware.

## Crib for questions

* **Encoding:** code k = 0..5 per cube is (front/back pair, left/right pair) = `CHOICES[k]`, on qubits 3c..3c+2, lowest bit first; codes 6, 7 are illegal.
* **Mixer:** per cube, a reflection about the equal mix of its 6 legal codes; it only moves amplitude between legal codes.
* **Why 4-local:** "cube c's chosen pair on this side contains colour k" is a 3-bit function; choosing its values on the unused codes 6, 7 makes it at most 2-local, and squaring the degree count multiplies two of them, so at most 4 Z's per term.
* **Oracle:** for each side and colour, "the colour appears exactly twice on the chosen pairs" (a same-colour pair such as BB counts twice); AND of all of them, built from the cube list only.
* **K formula:** K is the better of the two integers around pi / (4 theta) - 1/2 with sin(theta) = sqrt(M / 6^N); M = 2 gives K = 19 at N = 4.
* **Transfer:** the angles trained once at N = 4 are reused unchanged for N = 5..8.
